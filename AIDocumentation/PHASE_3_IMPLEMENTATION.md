# MATMA Python — Phase 3: Dependency Indexing and Persisted Reverse Graph

**Status:** Implemented and CI-verified on 2026-11-07. **6/6 GitHub Actions jobs passed** for Python 3.11–3.13 on Linux and Windows ([run 42402164370](https://github.com/rzepeda/matma-py/actions/runs/42402164370)). The suite passed 96 tests on Linux and 95 tests with one platform-specific skip on Windows.

**Design reference:** [accepted Python ADR-001](ARCHITECTURE_DECISIONS.md). The source **module**, not the Python class, is the atomic graph/test mirror node. Phase 2 `validate` and its source/module resolver remain read-only.

## Implementation

| File | Responsibility |
| --- | --- |
| `src/matma/indexing/graph.py` | Typed AST-resolved import/reference edges, conservative import-only dependencies, shortest weighted reverse-dependency levels, cycle handling |
| `src/matma/indexing/manifests.py` | Stable content fingerprint, per-module `.auto.yaml` and `.index.auto.yaml` metadata, safe ownership-aware deterministic regeneration |
| `src/matma/indexing/engine.py` | Full-index orchestration, validation and error statuses, target-as-response selector |
| `src/matma/cli.py` | Activates `index`; `index --scaffold`, `scaffold` and `impact` remain explicitly unimplemented |

The CLI never imports or executes consumer application modules, invokes pytest, generates tests/mocks, or rewrites production files.

## Edge policy: accepted Level 2 import-only decision

At index time, Phase 2 supplies per-module imports and actual AST references with their scope, type-only marker, resolved source path, and re-exports. Phase 3 converts them into typed, file-owned relationships:

- A statically resolved import **with a reference to its imported binding** contributes a weight-1 edge (`usage`, `inheritance`, `decorator`, `annotation` or `type_only`). On changes to the referenced source, the dependent module enters at **Level 1**.
- A statically resolved import **without a binding reference** still counts as a dependency, with weight 2 (`import_only` or `type_only_import`). That module enters the affected unit-test set **by Level 2**, even when the import was unused.
- `__init__.py` imports and re-exports are indexed as their own file dependencies. `from pkg import Export` references resolve through known re-exports; `import pkg; pkg.Export()` also follows the actually referenced initializer export. Unaccessed exports are not silently counted as direct usage by every sibling.
- Unresolved/external imports remain separately recorded rather than fabricated as internal edges. Dynamic import analysis is not performed at runtime.

**Levels use inclusive shortest weighted graph distance.** A two-edge chain of direct usage has distance 2; one unused import contributes distance 2 by itself. Longer paths add weights; cycles do not rediscover their origin. The manifest materializes `dependents.level_N` for every affected source file, retaining stable sorted source and test pointers.

This is a *conservative static model*, not a guarantee of complete Python runtime dependency resolution (e.g. monkey-patching, reflective lookups, complex alias assignments, wildcard imports). Business and regression suites remain separately authored and registered in later phases.

## Manifest format

```yaml
# AUTO-GENERATED BY MATMA PYTHON INDEXER - DO NOT EDIT MANUALLY
schema_version: 1
index_fingerprint: 'sha256...'
module_name: pkg.pricing
source_file: src/pkg/pricing.py
is_package: false
testable: true
symbols: []
mirrors:
  unit_test: tests/unit/mirror/src/pkg/test_pricing.py
  interaction_test: tests/interaction/mirror/src/pkg/test_pricing_interaction.py
  mock_file: tests/mocks/mirror/src/pkg/mock_pricing.py
  manifest: tests/mirror/src/pkg/pricing.auto.yaml
dependencies: []
external_dependencies: []
dynamic_references: []
warnings: []
dependents:
  level_1: []
  level_2: []
```

This is a schema illustration, **not a real generated example**. Empty levels may be absent. Actual dependencies include `module_name`, `source_file`, `weight`, a sorted list of `kinds`, optional resolved `symbols`, and evidence (import line and referenced lines). Dependent level rows carry `module_name`, `source_file`, `unit_test` and `interaction_test`. Each eligible module gets exactly **one** mirrored test-file pointer per tier; Phase 3 does not create the files.

`tests/mirror/.index.auto.yaml` includes schema version, shared fingerprint, configured source roots, source-file SHA-256 hashes, and known source directory modification timestamps. The fingerprint changes when indexed file contents or root configuration changes. Phase 5 will read these persisted data; Phase 3 does **not** yet implement an `impact` reader or claim constant-time end-to-end I/O.

## Safety and regeneration contract

- The complete AST inventory and structural validation succeeds **before any manifest writes**. An invalid target, parser error, unsafe root or ambiguous module identity fails indexing without writing new manifests.
- The entire graph always rebuilds, even when `--target` is passed, to prevent stale reverse dependents. `--target` affects only the response metadata.
- Output paths remain confined to the generated `tests/mirror/` tier. Symlinked destinations and traversal/overlap are rejected. All known destinations are preflighted before writing any file.
- A file without the exact MATMA-generated header is user-owned and **never overwritten**. Only MATMA-owned stale `*.auto.yaml` are deleted. Hand-written YAML elsewhere remains untouched.
- YAML is sorted/stable and written via temporary files plus atomic replace; byte-identical manifests are not rewritten, preserving modification times. Multiple-file writes are not a single transactional operation.
- The generated manifests are ignored by Git (without ignoring authored test files).
- `index --scaffold` returns explicit exit code `2` and creates nothing until Phase 4. `scaffold` and `impact` remain exit-2 shells.

## Commands and outputs

```bash
matma-indexer validate --check --format=json   # read only
matma-indexer index --source-root src --tests-root tests --format=json
matma-indexer index --target pkg.pricing --format=yaml
matma-indexer index --scaffold --format=json    # exit 2, no writes
```

`index` returns an envelope with `command`, `status`, `message`, `exit_code`, and validated `options`, plus the Phase 2 `summary`, `files`, `module_to_source`, `symbol_to_source`, `target`, `diagnostics` and the new `graph_summary`, `index_fingerprint`, `manifests.written|unchanged|removed`. Status is `indexed` (exit 0), `index_failed` (exit 1 for source problems) or `unsafe_output` (exit 1 for unsafe or unavailable manifest output). Actual file changes are reported, not inferred from class counts.

## Tests and Phase 3 acceptance

- Graph fixtures: a used import (L1), import-only (L2), a chained weighted dependency, chain/diamond, cycle, scoped imports, external imports, type-only/decorator evidence, deterministic order, `__init__.py` re-export accessed versus unused.
- Real temp-filesystem writer fixtures: byte-stable repeat indexing, content fingerprint changes, ownership conflict preflight, stale owned cleanup without deleting manual files, symlink rejection, index failure with no writes, and `--target` full-graph behavior.
- Black-box CLI fixtures: actual Phase 2 analyzer + generated YAML, imported-only L2, package re-exports, no scaffolding, invalid sources/targets, custom test/source roots, dynamic/static boundaries and output formats.
- The full package and consumer suite passed the six-job GitHub Actions matrix on Python 3.11, 3.12, 3.13 across Linux and Windows ([run 42402164370](https://github.com/rzepeda/matma-py/actions/runs/42402164370)). Windows CI exposed a CRLF-generated YAML ownership-header edge case, fixed by accepting LF/CRLF with a distinct regression fixture.

## Out of scope

Phase 4 creates runnable intentionally failing pytest tests and `unittest.mock` helper files. Phase 5 performs read-only impact selection, stale-manifest checks and separately registered workflow suggestions. Phase 6 includes benchmarks and release preparation. No performance gain is claimed until measured in a reproducible benchmark.
