# MATMA Python — Antigravity agent skill

This workspace skill guides Antigravity's coding agent when asked to
add tests, assess the blast radius of Python code changes, or manage
unit/interaction and business/regression testing using MATMA. It does not
install MATMA or enable shell permissions by itself.

Load `references/MATMA_CLI.md` for detailed flags, artifacts and
recovery rules before running the workflow.

## Workflow in the Antigravity workspace

1. Set the working directory to the **root of the target Python repo**.
   Inspect source roots, `pyproject.toml`, package layout and pytest files.
   Avoid rewriting existing production modules just to fit the tool.
2. Check the active Python interpreter (`>=3.11`) and
   `python -m matma --help`. If MATMA is absent, ask for installation
   approval and show the documented Git/local checkout option.
3. Validate structure with
   `python -m matma validate --check -o json`; resolve relevant errors.
   Respect existing `.py` modules containing many functions/classes.
4. Persist a full graph with `python -m matma index -o json` and confirm
   the `indexed` status before attempting impact selection.
5. If a task needs new tests, call
   `python -m matma scaffold --target pkg.module -o json`. It creates
   missing unit, interaction and mock helpers; existing files are never
   overwritten. Implement the failing templates with real assertions in
   both test tiers for the requested behavior. Don't skip tests just to
   hide their `pytest.fail` placeholders.
6. For changed modules, invoke
   `python -m matma impact --target pkg.module --level 2 -o json`.
   Inspect `tests.unit`, `tests.interaction`, `tests.missing` and optional
   `verification` paths. An **unused** import still enters selection at
   **Level 2**; actual symbol use starts at Level 1. Report gaps and
   dynamic import limitations.
7. When the user requests verification or the coding task requires it,
   run `python -m pytest` on the **existing** selected test paths and the
   explicitly registered business/regression tests. Running pytest is
   independent of MATMA; record real results and failures.
8. Present a concise walkthrough: touched sources, scaffold artifacts,
   impact level, affected tests, missing tests, warnings and commands run.

## Agent constraints

- Respect the Antigravity terminal permission and file access policies.
- Do not auto-install dependencies, execute app code to index, or claim
  user auth, test status, or CI results you cannot verify.
- On `stale_index` / `missing_index`, run an explicit `index` only when
  appropriate, or explain the required action.
- The verification registry is owned and maintained by the project, not
  generated by MATMA. Never infer unregistered business tests.
- All source-module mappings and mock lookup rules are in the reference file.
